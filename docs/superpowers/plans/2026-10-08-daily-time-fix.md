Reproduced with real TokenHub and isolated records: at 13:19, a follow-up “yes” for a 05:00 daily medication reminder produced editReminder scheduledAt=today05:00. Domain correctly rejected the past timestamp; MCP collapsed the reason into generic Invalid care change.

Add a restricted `setDailyReminderTime` tool/command with exact owned reminder ID, local HH:mm and optional explicit starting date. For no explicit date, choose the next future local occurrence using the existing Singapore scheduling contract. Preserve the same profile/series identity, all past and reported occurrences, medication instructions, and outcomes. Update only unreported future occurrences of that exact profile/series; create a missing anchor in that same series if needed. No cross-person/title matching or permission fallback.

Server normalizes the effective starting date during MCP validation, persists the typed command atomically under the existing auto-save/request-ID policy, and reports the actual starting date. Explicit past dates remain errors. Prompt directs daily-clock edits to this tool and distinguishes reminder notification schedules from medication directions. Improve only safe business-validation error feedback; no exposure of provider/credential details.
